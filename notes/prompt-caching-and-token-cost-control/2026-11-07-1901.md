## TIL: Prompt Caching and Token Cost Control

Prompt caching lets providers reuse the computed attention states (KV cache) of a static prefix—like system instructions or large context documents—across multiple requests. Instead of recomputing the prefix for every turn, the model loads the cached state, drastically reducing latency and **input token costs** (often 50–90% cheaper). This only works when the cached prefix is **identical** and placed at the **start** of the conversation; any mutation or dynamic insertion breaks the cache hit.

Cost control requires structural discipline: pin heavy context (RAG docs, few-shot examples, system prompts) to the immutable prefix. Keep variable user turns short and appended *after* the cached block. Monitor `cached_tokens` in API responses to verify hits; a miss usually signals a whitespace change, reordered messages, or a dynamic timestamp injected into the prefix.

```python
import openai, os, time

client = openai.OpenAI(api_key=os.getenv("OPENAI_API_KEY"))

SYSTEM_PREFIX = "You are a concise assistant. " + "Context: " + ("X " * 5000) # ~5k static tokens

def ask(user_msg: str):
    start = time.perf_counter()
    resp = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": SYSTEM_PREFIX},
            {"role": "user", "content": user_msg},
        ],
    )
    usage = resp.usage
    print(f"Latency: {time.perf_counter()-start:.2f}s | "
          f"Prompt: {usage.prompt_tokens} | "
          f"Cached: {usage.prompt_tokens_details.cached_tokens} | "
          f"Completion: {usage.completion_tokens}")

ask("Summarize the context in one sentence.")
ask("Translate that summary to French.") # Second call hits cache
```
